# 📖 Chapter Summary - Object-Oriented Programming

## 핵심 내용

- 프로그래밍 방식은 크게 절차 지향 프로그래밍과 객체 지향 프로그래밍으로 구분할 수 있음.
- 절차 지향 프로그래밍은 프로그램이 어떤 순서로 실행되는지에 초점을 맞추는 방식임.
- 절차 지향 프로그래밍은 데이터와 해당 데이터를 처리하는 기능이 서로 분리되어 있으며, 프로그램이 어떻게 동작하는지를 중심으로 코드를 작성함.
- 객체 지향 프로그래밍은 프로그램을 여러 객체의 모음으로 바라보고, 객체들이 서로 상호작용하도록 설계하는 방식임.
- 객체 지향 프로그래밍은 실행 순서보다 어떤 객체가 어떤 속성과 기능을 가져야 하는지에 더 집중함.
- 절차 지향과 객체 지향은 완전히 반대되는 개념은 아니며, 객체 지향 프로그램에서도 실행 순서는 중요함.
- 두 방식의 가장 큰 차이는 데이터와 기능을 어느 위치에서 관리하는지에 있음.
- 절차 지향 방식에서는 데이터와 기능을 별도로 관리하지만, 객체 지향 방식에서는 관련된 데이터와 기능을 하나의 객체 안에 함께 포함함.
- 클래스를 사용하여 관련된 데이터만 묶었다고 해서 객체 지향 프로그래밍이 되는 것은 아님.
- 데이터는 클래스 안에 있지만 해당 데이터를 사용하는 기능이 외부 메서드에 존재한다면 여전히 데이터와 기능이 분리된 구조임.
- 기능을 메서드로 추출하면 중복 코드를 제거하고, 코드의 역할을 분리할 수 있음.
- 메서드로 기능을 분리하면 동일한 로직을 재사용할 수 있고, 기능 변경 시 해당 메서드만 수정하면 됨.
- 메서드 이름을 통해 해당 코드가 수행하는 역할을 쉽게 파악할 수 있음.
- 여러 기능을 독립적인 메서드로 분리하는 것을 모듈화라고 할 수 있음.
- 절차 지향 방식에서도 데이터 묶음과 메서드 추출을 통해 충분히 읽기 좋고 유지보수하기 좋은 코드를 작성할 수 있음.
- 다만 데이터와 기능이 서로 다른 클래스에 분리되어 있으면 관련 코드의 관리 위치가 여러 곳으로 나뉘는 한계가 있음.
- 데이터 구조가 변경되면 해당 데이터를 사용하는 외부 메서드들도 함께 수정해야 할 수 있음.
- 자바의 클래스는 멤버 변수뿐만 아니라 해당 데이터를 사용하는 메서드도 함께 정의할 수 있음.
- 클래스 내부에 데이터와 기능을 함께 배치하면 객체가 자신의 상태를 직접 관리하도록 만들 수 있음.
- 객체의 메서드는 `객체.메서드()` 형태로 호출함.
- 객체의 메서드 내부에서 멤버 변수에 접근하면 해당 메서드를 호출한 객체 자신의 멤버 변수에 접근함.
- `static`이 없는 인스턴스 메서드는 객체를 생성한 후 해당 객체를 통해 호출해야 함.
- 객체는 속성과 기능으로 구성됨.
- 속성은 객체가 가지고 있는 상태나 데이터를 의미하고, 기능은 객체가 수행할 수 있는 동작을 의미함.
- 자동차는 색상과 현재 속도를 속성으로 가질 수 있고, 가속과 감속을 기능으로 가질 수 있음.
- 객체 지향 설계에서는 먼저 객체가 어떤 속성과 기능을 가져야 하는지 결정하는 것이 중요함.
- 객체를 사용하는 쪽에서는 객체 내부의 데이터를 직접 다루기보다 객체가 제공하는 메서드를 호출하여 기능을 사용함.
- 관련된 속성과 기능을 하나의 객체 안에 묶고, 필요한 기능을 메서드로 외부에 제공하는 것을 캡슐화라고 함.
- 캡슐화를 적용하면 객체 내부의 구현 방식이 변경되어도 외부에서 사용하는 메서드가 유지되는 한 사용 코드는 변경하지 않아도 됨.
- 객체 내부의 필드 이름이나 출력 방식이 변경되더라도 해당 객체 내부만 수정하면 되므로 변경 범위를 줄일 수 있음.
- 객체 지향 프로그래밍은 코드의 가독성과 유지보수성을 높이고, 실제 사물을 사용하는 것처럼 자연스럽게 코드를 작성할 수 있도록 도움을 줌.
- 실제 세계의 사물과 프로그램의 객체가 반드시 일대일로 대응되는 것은 아님.
- 객체 지향 프로그래밍에는 데이터와 기능을 묶는 것뿐만 아니라 캡슐화, 상속, 다형성, 추상화, 메시지 전달 등의 특징이 있음.
