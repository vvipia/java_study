# 📖 Chapter Summary - Polymorphism & Design

## 핵심 내용

- 다형성은 역할과 구현을 분리하여 구현 객체가 변경되어도 클라이언트 코드를 수정하지 않도록 설계할 수 있음.
- 클라이언트는 구현 클래스가 아닌 인터페이스(역할)에만 의존하는 것이 중요함.
- 구현 객체는 런타임에 자유롭게 교체할 수 있으며 다형성과 오버라이딩으로 동일한 방식으로 사용할 수 있음.
- OCP(Open-Closed Principle)는 기능 확장에는 열려 있고 기존 코드 수정에는 닫혀 있는 설계 원칙임.
- 새로운 기능이 추가될 때 핵심 로직은 변경하지 않고 구현체만 추가하는 구조가 좋은 설계임.
- 전략 패턴은 인터페이스를 통해 알고리즘이나 구현을 자유롭게 교체하는 대표적인 다형성 활용 사례임.
